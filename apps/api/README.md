# apps/api

FastAPI (Python) backend with PostgreSQL. Multi-tenant: tenant = agency (ADR-0005, ADR-0008).

## Local database (development only — the password below is for local use)
You need PostgreSQL 14+ on your machine. Easiest on this project's setup (WSL Ubuntu):
```bash
sudo apt install postgresql
sudo service postgresql start
sudo -u postgres psql -c "CREATE ROLE eskanban LOGIN PASSWORD 'eskanban' CREATEDB"
sudo -u postgres createdb -O eskanban eskanban
sudo -u postgres createdb -O eskanban eskanban_test
```
Alternative: the Windows PostgreSQL installer, then the same `CREATE ROLE` / `createdb` commands.
If the API runs in Git Bash but PostgreSQL runs in WSL and the connection fails, run the API inside WSL too.

## Run
```bash
cd apps/api
python -m venv .venv
source .venv/Scripts/activate        # WSL/Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
alembic upgrade head                 # create/upgrade tables
uvicorn app.main:app --reload        # http://localhost:8000/docs
```
- `GET /api/v1/health` – liveness (no database). `GET /api/v1/health/ready` – readiness (checks the database).

## First agency and login (mobile number + password)
There is no public sign-up: the operator creates each agency and its first manager.
```bash
python -m app.cli create-agency --name "Sunrise Realty" --slug sunrise --plan small --seats 3 \
  --manager-name "Ali Rezaei" --manager-phone 09121234567     # asks for a temporary password
python -m app.cli set-password --phone 09121234567            # forgot-password fallback for now
```
Then log in:
```bash
curl -s localhost:8000/api/v1/auth/login -H 'content-type: application/json' \
  -d '{"phone":"09121234567","password":"<temporary password>"}'
curl -s localhost:8000/api/v1/auth/me -H 'authorization: Bearer <access_token>'
```
| Endpoint | Who | Purpose |
|---|---|---|
| `POST /api/v1/auth/login` | anyone | mobile + password -> bearer token |
| `POST /api/v1/auth/logout` | logged in | end this session |
| `GET /api/v1/auth/me` | logged in | current user and agency |
| `POST /api/v1/auth/change-password` | logged in | change own password (ends other sessions) |
| `GET/POST /api/v1/users` | manager | list / add team members (seat limit applies) |
| `POST /api/v1/users/{id}/deactivate` | manager | deactivate (ends their sessions) |
| `POST /api/v1/users/{id}/reset-password` | manager | set a temporary password |

Errors use one shape: `{"error": {"code": "...", "message": "..."}}`.

## Property files and reference data
Everything below needs a login without a pending password change (otherwise `403 password_change_required`).

| Endpoint | Who | Purpose |
|---|---|---|
| `GET /api/v1/properties` | logged in | list with filters, sorting, pagination (see the OpenAPI docs) |
| `POST /api/v1/properties` | logged in | create a file (a manager may set `owner_user_id`) |
| `GET / PUT /api/v1/properties/{id}` | visible / owner or manager | read / replace a file (`version` required, 409 on conflict) |
| `POST .../{id}/status` | owner or manager | active, inactive or closed (+ deal date) |
| `POST .../{id}/favorite` | logged in | toggle your personal star |
| `POST .../{id}/share`, `/reassign`, `/soft-delete` | manager | share with the agency, change owner, delete |
| `GET .../{id}/history` | visible | change log |
| `GET /api/v1/properties/similar`, `/stats` | logged in | possible duplicates, dashboard counts |
| `GET /api/v1/vocab` | public | controlled lists with Persian and English labels |
| `GET /api/v1/geo/provinces`, `/cities`, `/districts` | logged in | provinces, cities, districts used by the agency |

Money is whole Toman; dates are ISO (Gregorian); areas are numbers. Province and city data comes from
`alembic/data/` (MIT licence, see the notice there).

## Migrations (Alembic)
```bash
alembic revision --autogenerate -m "add files table"   # then READ the generated file
alembic upgrade head
alembic downgrade -1
```
Always review autogenerated migrations before committing, and test both upgrade and downgrade.

## Checks
```bash
pytest          # needs the test database; skips with a message if PostgreSQL is not reachable
ruff check .
```
In CI (`CI=true`) an unreachable database fails the run instead of skipping.

## Structure
```
app/
  main.py            app factory, middleware, routers
  core/              config (ESKANBAN_* env vars), domain errors
  db/
    base.py          declarative Base + constraint naming
    models/          Agency, User, AuthSession, Property*, Province, City (+ mixins)
    session.py       engine, session factories (tenant / system / unscoped)
    tenancy.py       automatic tenant scoping + write guard
    url.py           normalises postgres:// URLs for SQLAlchemy + psycopg 3
  services/          business rules (agencies.py, auth.py, properties.py)
  domain/vocab.py    controlled lists (deal types, amenities, document types, ...)
  schemas/           request/response models
  api/               deps.py (auth + tenant sessions), errors.py, v1/ routers
  cli.py             operator commands (create-agency, set-password)
alembic/             migrations
tests/               pytest (runs the real migrations on PostgreSQL)
```

## Tenancy rules (read before adding any table)
- Every table owned by an agency uses `TenantMixin` (adds `agency_id`).
- Application code uses `tenant_session(agency_id)`; `system_session()` is only for provisioning and workers.
- Query with ORM entities only. Raw SQL (`text()`) and `Table` objects bypass the tenant filter.
- Every new tenant table needs an isolation test (see `tests/test_tenancy.py`).
